## 实现位置与明确边界

- `server/app/creative_templates/`：Schema/语义准入、能力注册、确定帧展开与受限 D 编译。
- `server/local/templates.py`、`template_api.py`：资源、不可变修订、草稿、消息事务、实例、编译回执、报告、生命周期及人工审阅接口。
- `server/local/commands.py`：prepare、confirm、Worker 三个入口校验精确报告，交付保留模板引用。Agent 走共享业务服务，不能伪造人工批准。
- `web/templates/` 与 `web/main.tsx`：作者/公开库、独立骨架图、槽绑定、无项目草稿、刷新恢复、提交幂等和历史实例详情。
- `server/resources/workbench-d/references/template.md`：给 Agent 的明确适配对象契约。真实试作暴露出只有宽泛 object schema 时 Agent 会猜测参考路径和 occurrence ID，已补充文档、工具字段说明、实例展开结果与错误中的有效 ID。失败适配按幂等命令持久计数，超过 `max_plan_repairs` 后必须人工介入，重复同一命令不额外消耗修正次数。

方案中的实体以现有 `facts` 表的独立 kind 命名空间、唯一复合键和控制库事务实现，没有新增同名物理 SQL 表。旧工程无需数据库迁移；这属于存储实现差异，不改变精确版本/事务/幂等要求。

当前原生编译器明确限定独立片段视频生成、顺序合成、片尾文字及人工审片。不支持的图结构、公共制作素材、生成间依赖、模型角色组合会阻断；不会丢弃输入后声称成功。`template_routes` 必须由操作者配置。原 `config.local.json` 未修改，原应用尚未配置这条路线；本次真实试作在独立配置中接入现有账号。

T0～T3 的上述实现与非付费验证已完成。T4 的跨产品实测、人工审阅、可发布样片和正式发布仍需实证；T5 未实现。不能将整项计划标为全部完成。
