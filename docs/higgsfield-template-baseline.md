# Higgsfield 模板体验调研与产品基线

调研日期：2026-10-19。状态：产品设计，未实现。通过官网帮助、公开页面和浏览器实际界面核对；未上传素材、提交生成或验证成片质量。以下明确区分观察事实和我们的实现方案，不推测其私有提示词、模型编排或模板文件格式。

## 核对到的体验

| 入口 | 实际看到的内容 | 对我们的启示 |
|---|---|---|
| [Marketing Studio](https://higgsfield.ai/marketing-studio) | 视觉模板目录；Product shot、Motion、UGC、TikTok、Ads、Posters、Marketplace；图片/视频筛选；My generations、My favorites；另有自由描述入口 | 模板以效果预览和用途组织，报告与执行结构不占据用户主流程 |
| [Before and After](https://higgsfield.ai/marketing-studio/preset/before-and-after-3728af13-8efa-4703-a10f-69b142c2df52) | 左侧样片；右侧 Recreate template；产品上传标为必需，人物可选；修改描述；可替换 Hook 与 Setting；Recreate 按钮显示积分 | 模板包含默认效果和可替换组件，输入依类型变化。不是所有模板都应暴露所有字段 |
| [Green Tea Macro](https://higgsfield.ai/marketing-studio/preset/green-tea-macro-6089a97b-4e49-43ed-9338-09a9c63e2783) | 必需的产品上传、修改描述、Recreate | 产品动效可以有很少的用户输入；没有必要让用户先写营销策略和分镜 |
| Marketing Studio 的 Ad Reference 弹窗 | 参考广告视频、产品、人物入口以及 Continue；说明强调保留开场吸引方式与表达能量 | 参考广告复刻是独立入口，可与已上架模板复用共享后端 |
| [Billboard Ad](https://higgsfield.ai/apps/billboard) | 图片上传、广告牌文字、生成视频；示例呈现既定广告牌效果 | 单效果 App 与完整营销叙事模板应区分 |

浏览器读取到了动态弹窗；网页文本抓取对具体 preset 页面主要只返回目录壳，因此上述弹窗字段以实际 UI 为依据。没有操作人物库、历史作品或私有资产。页面上的积分只代表观察时当前配置，不能作为固定成本。

[官方 Marketing Studio 帮助](https://higgsfield.ai/creator-hub/help-center/tools/how-do-i-use-marketing-studio-to-create-video-ads)说明：可从模板开始，通过产品图或产品/网站链接提供品牌信息；品牌套件用于复用身份；模板路径无需用户编写提示词。帮助页也描述了参考广告路线。以上是官方功能说明，链接提取与身份保持效果本次未实测。

官方帮助与新产品入口存在版本差异：帮助页称模板路线尚未进入 MCP，但[官方 API 已公开 Marketing Studio Image](https://open.higgsfield.ai/models/marketing-studio/image/playground)。图片 API 的存在不能证明整个网页视频模板库可被 API 调用。本方案采用其体验作为基线，不依赖调用 Higgsfield 服务。

## 修正此前的模板定义

此前的结构化契约能作为后台设计基础，但把全部执行输入当作用户必填、把逐镜头人工确认设成通用流程，会造成与基线不同的使用体验。

模板的产品定义改为：**一个有可观看样例、明确适用对象、少量替换入口、默认创意与执行配方的可运行创作预设。**

用户选模板时已经选定了大部分创意。Codex负责替换、适配和执行规划，不能在未请求时重新发明风格与广告结构。计划可供用户展开查看，但不是默认使用门槛。

同一模板包同时包含：

1. 展示层：名称、分类、样片、适用产品、输入要求、可选组件、输出规格。
2. 交互层：产品输入方式、字段默认值、条件必填、品牌库选择、修改描述与高级选项。
3. 创意层：基础钩子、叙事节奏、视觉/声音配方、可替换 Hook/Setting/Avatar 组件及组合限制。
4. 执行层：资产绑定、身份约束、模型输入角色、任务依赖、成本估算、D能力映射与检查项。
5. 验证层：自制或可分发样片、跨产品试运行、执行回执、已知限制与版本。

上述分层是我们的设计，不是 Higgsfield 内部格式的披露。

## C端默认路径

```text
浏览可播放样片 → 选模板 → 上传产品图 / 选已有产品 / 提供产品链接
→ 按需调整人物、钩子、场景、文案 → 查看本次费用 → 生成
→ 查看成片 → 下载 / 再生成 / 可选进入D编辑
```

一期本地插件先实现同样的选模板、绑定产品、调用制作流程；网站目录与产品链接自动提取可以分阶段上线。未实现的入口不展示可用状态。后续 SaaS 复用同一模板包和实例契约。

输入分成用户提交、品牌库读取、系统推导、执行前检查四类。普通产品展示模板默认只要求一张清晰产品图；独立Logo、其他视角、演示视频按镜头需求再索取。文字不清晰时不能自动重画商标；需要真实功效证据的模板也不能仅靠产品图自动填出效果证明。

身份描述、镜头锚点与结构化提示词仍然存在，但通常由系统建立。标准路线使用经验证的自动检查和有预算上限的返工；只有缺少关键资料、检查失败或用户开启专业模式时才中断请求处理。当前执行能力若强制人工确认，必须标为辅助制作路线，不冒充一键模板。

用户主动点击生成授权该次显示费用/上限下的任务。修改产品、付费模型路线或超出返工预算，必须重新报价。内部阶段推进不增加重复确认弹窗。

## 可替换组件如何约束 Codex

每个模板声明默认组件及可替换集合，组件提供输入要求、时长范围、适用产品、与后续beat的连接条件。`No hook`等界面标签不能直接推定内部语义；我们的格式需明确区分“保留默认钩子”“替换钩子”“移除钩子”。

用户替换钩子时，实例保留基础模板版本和组件版本，重算开场时长及后续衔接。只有可组合的组件才出现在选择器。将“结果先行”改成“采访开场”不能仍然声明满足原来前两秒展示结果的不变量：应使用组件提供的新规则，或标记为新变体。

普通修改描述先解析为受允许参数差异。只请求换背景时，产品身份、主要节奏、镜头功能保持；要求越过模板适用范围时提示更合适的模板或创建显式变体。

## 采集插件主流程的最终产物

```text
采集视频 → 人工选中 → Gemini观察与拆解 → 模板草稿
→ 作者选定可复用效果和可替换组件 → D制作样片与跨产品试运行
→ 发布就绪模板包 → 模板卡上架 → 用户实例 → D任务计划与成片
```

研究报告留在作者端作为出处与判断依据。消费者获得可套用的模板；JSON是后台载体。原爆款视频的高分、Gemini给出的完整报告或合法JSON，都不足以说明模板已可用。

上架包须含可展示样片、最小输入契约、创意及执行配方、组件兼容信息、实际试运行记录；无样片/回执则保持草稿，不把源广告冒充本系统生成效果。来源表现分、模板制作成功率、生成质量和预测传播分单独记录。

## 验收基线（我们的目标）

| 项目 | 验收条件 |
|---|---|
| 看效果选模板 | 每张上线卡可播放本系统实际做出的授权样片，显示适用对象和输入要求 |
| 少量输入 | 普通产品展示模板一张图可进入生成；其他类型明确解释额外必需素材 |
| 无提示词也可用 | 用户不写prompt，系统仍能生成完整实例；修改描述可选 |
| 可控替换 | 支持模板声明的产品/人物/钩子/场景替换；不支持的组合不暴露 |
| 继承创意 | 规划和产物能追溯每个beat与选中组件，不因换产品丢失节奏与关键动作 |
| 身份与费用 | 图片实际进入生成输入；标识检查；提交前显示费用；返工有上限 |
| 结果闭环 | 可查看、下载、再生成；D编辑作为额外入口 |
| 可复用验证 | 建议每个首发模板至少试3种兼容产品并记录失败，不把此小样本称为统计成功率 |

第一批应优先选择能稳定完成的产品亮相、场景展示、视觉反差等模板。真实功效演示型继续要求证据，单列为素材要求更高的类别。[原20秒示例](D:/P-project/VideoCopyer_SaaS/docs/examples/product-demo-template.example.json)属于这种严格类型，不能作为所有模板的默认表单。[精简体验示例](D:/P-project/VideoCopyer_SaaS/docs/examples/product-reveal-template.example.json)说明新基线；两者均未实现或试运行。
