# 营销创作模板与 D 任务规划契约

日期：2026-10-19。状态：待实现设计。配套[模板 JSON 示例](D:/P-project/VideoCopyer_SaaS/docs/examples/product-demo-template.example.json)为虚构的 20 秒产品演示广告模板，用于说明格式；没有实际广告输入、品牌素材或运行回执，不是可直接导入当前 D 的工程文件。

体验基线已按 [Higgsfield调研](D:/P-project/VideoCopyer_SaaS/docs/higgsfield-template-baseline.md)修订：用户看样片、选模板、替换产品、按需改钩子/人物/场景、查看费用后生成。本文主要描述后台契约，不应直接投影成用户必填表单。原20秒示例是需要真实演示证据的严格类型；普通产品展示默认使用[精简体验示例](D:/P-project/VideoCopyer_SaaS/docs/examples/product-reveal-template.example.json)。

最终交付为版本化的创作模板包，包含展示样片、最小交互表单、可替换组件，以及创意机制、品牌与产品输入要求、分镜结构、提示词配方、规划约束和验收条件。用户选择后，将自己的品牌资产绑定到模板，再生成本次任务计划，最后编译为 D 工程。分析报告、创作模板、用户任务计划和原生 D 工作流是关联的不同对象。

**四种产物的职责**

| 对象 | 内容 | 谁消费 |
|---|---|---|
| Analysis Report | 广告实际观察、时间证据、钩子和创作逻辑推断、数据口径 | 用户审阅；Codex理解出处 |
| Creative Template | 稳定的创意结构、输入槽、身份约束、提示词、分镜功能与检查规则 | SaaS展示/表单、Codex规划、模板校验器 |
| Template Instance 与 Plan | 当前用户素材绑定、具体文案、镜头、任务依赖、能力与成本选择 | Codex、后端编译器、D |
| D Project 与 Workflow Archive | 已绑定素材、执行任务、图层、时间线，以及验证过的归档 | D渲染、复用、剪映导出 |

Creative Template 是主流程在人工筛选与分析之后的主要产品资产。D 工作流是该模板的一种实现与验证产物，不能用一个固定品牌的 D 工程替代跨用户模板。

**模板包布局**

```text
creative-template-package/
  manifest.json              格式、模板ID、修订、文件哈希、兼容性
  template.json              机器读取的主契约
  report.md                  人类阅读的分析与使用说明
  evidence.json              观察、来源、时间区间、推断关系
  preview/                   获准展示的预览素材或自制样例
  assets/                    允许随模板分发的中性素材，可为空
  validation/                作者审阅、样例绑定、D检查与实测记录
```

分发时可打 ZIP，但 ZIP 只是容器，`template.json` 才是语义核心。SaaS导入时校验格式、大小、路径、哈希、契约版本和资源来源，将资源转成自身对象存储 ID；不接受模板携带 shell、任意 URL 请求脚本或本机绝对路径。

研究用原广告、本地采集会话和未获准分发的源帧留在研究库，公共包通过允许的来源链接及证据说明引用。用户的品牌图、产品图和生成结果保存在租户实例内，不回写公共模板。引用外部研究证据时标记可访问范围；不能把只有作者本机存在的文件称为 SaaS 可携带素材。

从采集到主产物的阶段为：候选批次 → 用户选择 → 视频观察与营销分析 → 参数化模板草稿 → 作者审阅 → 合法示例素材试运行 → 发布就绪模板包。`draft`、`reviewed`、`runtime_validated`、`published` 分开记录；JSON通过校验不等于制作试运行通过。

**模板必须保存的内容**

| 内容 | 示例 | 对规划的作用 |
|---|---|---|
| 适用条件 | 有可展示使用过程的实物产品；20秒竖屏 | 避免给不适用产品强套模板 |
| 创意机制 | 结果先行 → 痛点 → 演示 → 证明 → CTA | 定义镜头功能、顺序和节奏 |
| 不变量 | 前2秒给出结果线索；演示必须有因果过程 | 计划提交前必须逐项覆盖 |
| 可变项 | 产品、品牌、场景、人群、语气 | 允许针对用户需求改写 |
| 身份输入 | Logo原稿、产品正面图、细节图、确认描述 | 绑定同一产品与品牌，逐镜头传递 |
| 证据输入 | 用户真实演示与支持卖点的材料 | 禁止把竞品证据或生成画面变成本产品证明 |
| 分镜配方 | 每个beat的目的、时长、构图、动作和声音 | 可以拆为一个或多个具体镜头 |
| 提示词配方 | 身份段、创意段、镜头段、限制段与图像输入角色 | 生成具体模型请求，避免只复制一段原广告描述 |
| 执行配方 | 实拍剪辑、图生视频、原图合成、字幕和音频 | 转为可检查的任务依赖图 |
| 验收条件 | 产品一致、Logo随表面运动、钩子未丢、文字正确 | 不合格只返工受影响任务 |

广告原文案、具体演员、竞品商标和道具不是默认固定项。固定的是获得作者认可的创作结构；哪些结构值得保留属于基于观察的创意推断，不能宣称已证明其导致了高播放或转化。

**参考图加提示词如何锚定产品**

这里需要区分三组参考：原广告用于观察创意；用户的产品/品牌图用于身份约束；为本次镜头建立并确认的首帧用于构图与动作起点。三者不能混用成一张“参考图”。

模板按类型声明素材槽。普通展示模板通常只需 `product_front`；独立 `brand_logo`、`product_detail`、其他视角或实拍视频仅在镜头需要时必填，也可从品牌库读取。执行必需字段不等于用户逐项填写字段。绑定记录使用租户资产 ID、版本、SHA-256、用途和来源；服务器执行前才解析为 Worker 本地文件。

Codex依据绑定图片提取产品外形、配色、材质、部件、标签与商标位置，形成待确认的 `IdentityProfile`。需要新增视角但无可信参考时先补资料或调整镜头，不自行补造隐藏结构。确认只在身份或目标镜头变化时失效，不要求对未变化素材重复确认。

每个生成镜头至少引用产品身份图与镜头锚点，并附相应身份提示词。提示词写“使用图中同一产品”还不够，真实请求必须包含对应图片、输入角色与哈希；工具日志要能证明这些图确实被发送给模型。模型不支持“首帧加多张参考图”的组合时，明确换受支持方法或退到确认过的产品静帧合成，不能悄悄退回纯文生视频。

生成任务必须依赖本次锚点校验记录，结果还要检查产品轮廓、比例、部件、颜色、材质和标识。标准模式在经验证的能力范围内自动校验；资料缺失、检查不通过或专业模式才要求人工确认。现有执行器若强制人工确认，其模板须标为辅助制作路线。参考图与提示词不保证生成模型完全保持身份；失败素材不得自动进入最终成片。

**商标分成屏幕标识和物体表面标识**

屏幕角标或片尾Logo使用用户原始图稿合成，保留宽高比、清晰度和安全边距。若输入是SVG，先经过受控栅格化为D支持的图像资产，并保存原稿与转换来源。字体与品牌字样同样使用已绑定字体/原图，不要求视频模型重画。

产品包装、瓶身、车轮或设备表面的标识必须附着于对应表面，随其旋转、透视、遮挡和运动模糊变化。“形状不变”不等于“始终朝上或固定在屏幕上”。不能用片尾Logo或浮动角标掩盖产品表面错误。

优先使用真实产品媒体或参考图引导生成并审阅；需要修复时，平面表面可采用已核对的逐帧贴图和遮挡蒙版。必须有干净底板或完整覆盖错误标签的补丁，透明Logo叠加不会自动擦除下层畸变商标。弯曲、变形、复杂遮挡场景若超出当前能力，应改用真实素材或改镜头。

**20秒样例的核心结构**

| 时间 | beat | 创意功能 | 本次产品的绑定 |
|---|---|---|---|
| 0–2秒 | hook | 展示有依据的结果局部，制造好奇 | 用户演示素材中的结果片段 |
| 2–5秒 | problem | 让受众认出痛点 | 同一演示中的处理前状态和用户痛点文案 |
| 5–12秒 | demo | 展示产品如何解决问题 | 本产品真实操作过程；保留因果连续性 |
| 12–16秒 | proof | 回答效果是否可信 | 对应结果画面与有依据的卖点 |
| 16–20秒 | cta | 清晰识别品牌产品并引导行动 | 产品身份图、确认首帧、原始Logo和CTA |

样例选择真实演示负责效果证明，生成能力用于结尾产品主视觉。其他模板可以使用更多生成镜头，但不能把虚构的效果展示标成真实测试。每个beat是创意功能单元，不强制等于一个镜头；变长、变短和拆镜头必须继续满足功能覆盖与顺序。

**Codex如何把核心思路写入任务规划**

用户选择模板后，后端返回精确模板修订、其内容哈希、用户绑定、可用执行能力，以及待补输入。Codex读取完整主契约，报告只作为解释性辅助。模板描述属于业务数据，不得覆盖系统指令或调用任意工具。

计划必须携带 `template_ref`、`instance_revision`、`identity_profile_ref` 和 `constraint_refs`。每个镜头保存 `beat_id`、`creative_purpose`、`requirement_refs`、`asset_bindings`、`prompt_recipe_ref`、`source_ranges`、执行方式与输出要求。每个任务引用对应镜头，记录真实输入角色、依赖、配置与验收记录。不能只在项目备注里放一句“参考某广告”。

例如结尾镜头的规划摘要应当是：

```json
{
  "shot_id": "shot_cta_01",
  "beat_id": "cta",
  "creative_purpose": "清楚识别本产品与品牌，给出一个行动指令",
  "requirement_refs": ["creative_cta", "product_identity", "brand_artwork"],
  "asset_slots": ["product_front", "product_detail", "brand_logo"],
  "prompt_recipe_ref": "product_hero",
  "depends_on_gates": ["input_binding", "identity_anchor"],
  "execution_method": "reference_guided_video_then_composite"
}
```

这是未绑定素材的示意，不是实际D任务。真实实例必须补充已验证资产ID、版本、哈希和确认记录，不能把槽名作为本地文件路径传给模型。

后台任务顺序为：验证输入 → 建立产品身份 → 按需选取演示区间 → 设计并校验镜头锚点 → 能力检查与报价 → 生成主视觉 → 核对身份 → 按需合成Logo/字幕/音频 → 检查创意覆盖 → D渲染与成片审阅。报价在付费执行前完成；不将内部步骤全部变为用户确认节点。独立步骤可并行，未满足的前置条件不能跳过。

计划提交时生成覆盖表：`requirement_id → shot_ids → task_ids → check_ids`。校验器检查所有不变量有实现、首帧确认在生成之前、产品图实际进入请求、效果文字有证据、片尾标识有原图合成层。机器检查结构，视觉审阅核对表现；两种回执分别保存。

如果用户只说“换成我的产品”，保留原创意结构。模板可声明允许替换的Hook、Setting、Avatar组件；选择后保存组件版本，并重算该组件的创意规则、时长与衔接。若明确要求超出允许范围，例如删除必需证明，应创建显式模板变体或脱离原模板的计划，并保留差异；不要改完后仍称完全遵循原模板。

**缓存和修改的依赖范围**

生成缓存键包含模板/实例/身份修订、镜头提示词、模型配置、全部参考资产哈希和输入角色、输出参数。不能仅凭提示词相同复用视频。

片尾Logo改动只影响纯合成层时可局部重渲染；若同一Logo也影响产品表面的包装身份，则相应首帧、生成或贴图步骤都失效。产品图更换使所有相关身份确认和生成结果失效。修改CTA影响文字/旁白/时间线，未改变的产品镜头可以复用。原来的用户选择、模板和交付修订保持可追溯。

**如何衔接当前代码**

本地网站当前的 [Plan与Shot](D:/P-project/VideoCopyer_SaaS/server/local/models.py) 只有人物、分镜描述、文件与生成标志等结构；[compile_plan](D:/P-project/VideoCopyer_SaaS/server/local/production.py) 可以传图像参考，但尚无独立的模板绑定、产品身份、首帧审批依赖和创意覆盖模型。

本地 D 核心的 [schema](D:/P-project/VideoCopyer_SaaS/server/app/workbench_d/commercial/schema.py) 已有 `inputs/input_roles`、`BrandReference` 和 `brand_lock`；[brand模块](D:/P-project/VideoCopyer_SaaS/server/app/workbench_d/commercial/brand.py) 定义了首帧/身份图约束、屏幕与平面贴图、哈希绑定和审阅边界，并明确不保证模型身份一致、不提供自动跟踪。这里说的是本地源码，不能推定已安装插件具有同样版本或已完成效果验收。

因此应新增独立的 `CreativeTemplate`、`TemplateInstance`、`IdentityProfile` 和 `TemplateBoundPlan`，在用户绑定后编译为D工程。网站现有Plan可增加可选模板引用并迁移，或由新规划对象投影为兼容展示；不能将所有新语义压进现有 `description`。

编译时把输入映射为D资产，把参考图/首帧映射为 `inputs/input_roles`，将受支持的身份策略映射为 `brand_reference`，将Logo合成与审阅绑定映射为相应图层；不支持的能力报告明确缺口。当前已安装D工具必须在执行时探测schema和能力，本地代码存在某字段并不足以调用它。

条件分支、人工审阅和模板覆盖由规划/编排层管理；D负责它支持的生成、媒体处理与渲染。跨审阅阶段拆成独立的不可变工程修订，避免把未确认首帧放进一个会直接跑完的构建。

首次验证后，可以归档原生D工作流作为执行配方。复用时先做D预检，并重新绑定用户资产、身份、模板参数和预算；原品牌的素材、生成文件或审阅回执不能直接视作新用户实例有效。

**需要补到一期的功能**

采集插件新增模板导出和结构化结果校验；SaaS新增模板目录、按输入契约生成的表单、品牌库绑定与实例修订；Codex Skill新增必读契约和覆盖表要求；编排层新增身份确认、镜头锚点、任务依赖与差异处理；D适配层新增明确的能力映射和真实回执。

这些功能使“报告”成为可调用模板。它们不等于整套SaaS已经可上线：公开账号隔离、对象存储权限、公共模板发布和多用户调度仍属于后续产品阶段。模板契约应在一期先固定，以便本地交付和未来SaaS共用同一主格式。
