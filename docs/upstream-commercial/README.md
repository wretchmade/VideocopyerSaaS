## 实际架构

```text
D MCP / D HTTP / D 前端
        ↓ 同一 dispatch
D Project v1 → 校验 / 升级 → 不可变修订 + 素材内容寻址快照
        ↓                   SQLite 命令回执、状态与事件
冻结修订 + 运行时哈希 → 持久任务图 → detached worker + 可续租执行权
        ↓                         ↓
Playwright 独立上下文          Pillow 帧合成与字体测量
截图 / 定步交互记录               ↓
        └────────────→ LGPL FFmpeg + OpenH264 / AAC / alpha MOV
                                  ↓
                         帧数 / 时长 / 音轨 / 哈希校验
                                  ↓
                         交付副本与绑定修订的回执
```

`schema.py` 定义工程和帧域约束；`store.py` 负责数据库事务、幂等回执与租约；`engine.py` 管理工程、计划、提交和交付；`worker.py` 调度依赖与恢复；`render.py` 合成；`capture.py` / `browser.mjs` 采集。`processes.py` 使用 Windows Job Object 管理子进程树，取消/异常会清理 Chromium 子进程。

`app.main_d:app`、`app.workbench_d.external_mcp_server` 和原 `/api/d-production` 已接到新内核。商业入口不暴露未迁移的旧模型/组件命令，不把不可用的后续功能转发给 Hypit。旧前端的完整分组画布不是本次的新内核界面；当前提供真实项目列表、工程编辑、修订、逐帧预览、渲染、恢复、取消和交付。

数据位于 `D_CORE_DATA/core`。项目与修订不删除，素材按 SHA-256 固化，命令 ID 绑定规范化请求。相同修订和运行时的重复构建复用同一个 build；同一 commandId 换请求会报错。工作进程退出后 10 秒租约到期，由服务恢复循环或查询重新派发。每次尝试独立目录，旧执行器不能覆盖新执行器的产物；完成的任务节点校验哈希后复用。中断在节点内部会重做该节点，不能把这称为外部动作的 exactly-once。

## 实现顺序及阶段验收

1. 锁定原始包、迁入 D 源码并记录来源，枚举依赖、文档、TGZ、字体和扩展边界。
2. 定义 D Project v1、严格字段校验和显式版本升级；素材内容寻址，修订并发保护。
3. 建立持久回执、依赖图、独立执行、租约恢复、取消及重试；再接渲染。
4. 实现多轨、裁切、布局、透明度、关键帧、重叠淡入淡出、文本和逐帧输出。
5. 接通独立浏览器采集、字体验证、音频样本时钟和成片检查。
6. 替换 D 的生产入口、建立只读旧工程桥接，跑真实 MCP、HTTP、界面和同素材对照。
