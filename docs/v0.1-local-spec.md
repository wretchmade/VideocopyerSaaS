**VideoCopyer 本地 v0.1 产品和实施规格**

日期：2026-10-19。目标：交付本机可启动、真实 Codex 驱动、支持用户完整测试两轮的视频制作 Web 应用。用户在会话中开始工作，所有规划、执行、反馈和交付均归入同一个项目。两轮测试通过后进入服务器试运行准备；公开多用户收费还需要独立通过权限、计费和并发验收。

当前为实施规格，开发与测试项均待完成。技术选择为建议默认值；模型账户、测试预算和剪映目标版本在首次真实验收前确定，不把默认值当作付费授权。

**产品边界**

本地版采用单用户、多项目模式；项目之间保存独立会话、素材、规划、任务和结果。浏览器连接本机服务，不依赖用户持续打开当前 Codex 桌面任务。网页左侧是真实 Codex 运行时的会话客户端，不是嵌入或读取当前桌面 Codex 窗口。

v0.1 交付首页会话、项目工作台、文件上传、人物与分镜规划、真实工具执行、暂停与恢复、预览播放、配套剪映工程下载、本地安装辅助和成本记录。支持一套已验证的文本、图片、视频、配音配置，按项目实际需要启用。

账号注册、支付充值、团队协作、自动扩容、任意第三方插件安装、任意模型供应商、完整剪辑软件和全部历史效果对齐不进入本轮。保留 owner、预算、用量、文件服务和任务接口，为后续扩展提供边界。

**用户主链路**

1. 用户打开首页，直接输入需求，可同时上传参考图、视频、音频或文字资料。
2. 系统先持久化输入和附件，再创建项目及绑定会话，自动导航到 `/projects/{projectId}`。重复点击或网络重试不创建重复项目；首次消息原样保留。
3. Codex 提炼目标、片长、比例、风格、人物、参考素材及预算。缺少影响制作的信息时在左侧提问；右侧逐步出现对应规划卡片。
4. 用户通过对话修订方案，也可以选中右侧卡片后发出“修改这个镜头”等带对象上下文的请求。
5. Codex 提交结构化方案；后端验证并保存修订，右侧显示真实保存结果。开始收费生成前显示范围和预算，用户可授权在该范围内继续执行。
6. 服务执行人物参考、分镜素材、配音、字幕和合成。会话中显示简短进展及工具结果，画布展示各步骤真实状态与可用素材。
7. 生成预览片。用户可直接说“第二个镜头缩短两秒”“这个人物换服装”“字幕大一点”，系统产生新修订，只重做确实失效的内容。
8. 用户确认某一版预览，下载该版 MP4 和配套剪映工程 ZIP；本地安装辅助可将工程放到新目录，用户在剪映打开、编辑、保存并重开。
9. 关闭浏览器或重启服务后，从项目列表返回，能够读取会话、规划、任务及已生成结果；未知远程提交先对账，不能自动重复付费。

**页面和交互**

| 页面 | 内容与行为 |
|---|---|
| `/` | 会话输入、附件上传、最近项目、运行环境状态；用户不用填写工程 JSON |
| `/projects/{projectId}` | 项目专属工作台；默认左 38%、右 62%，分栏可拖动并记忆；窄屏切换会话与画布 |
| 项目顶部 | 项目名称、整体状态、预算摘要、预览、导出、返回项目列表 |
| 左侧会话 | 流式文本、附件、工具活动折叠项、用户选项、执行授权、停止与继续、错误恢复入口 |
| 右侧画布 | 创作目标、人物、分镜、素材任务、成片节点与依赖关系；节点可选中、折叠、拖动和缩放 |
| 右侧详情 | 点击人物、镜头或任务查看具体内容、参考素材、结果与状态；支持选中对象后发送修改 |
| 预览与交付 | 工作台内打开播放器与交付抽屉，保留会话；明确展示当前预览和工程对应的版本 |

右侧采用面向创作的文案和卡片：人物姓名、镜头描述、时长、画面、配音、字幕及缩略图。原始 JSON、完整工具参数和诊断信息放入调试区。模型输出的文字不自动视为已完成操作；画布只以服务端确认的状态为准。

页面刷新后通过事件游标补齐内容，不重新发送用户消息。工具失败显示可理解的原因及恢复动作。用户看到“停止”时应能区分停止 Agent 推进、取消待执行任务以及请求取消已提交的供应商任务。

**最小规划数据**

| 对象 | 必需内容 |
|---|---|
| Brief | 目标、受众、片长、画幅、风格、输入素材和约束 |
| Character | 人物 ID、描述、参考图版本、服装、声音配置、确认状态 |
| Shot | 镜头 ID、顺序、时长、人物引用、场景、运动、台词、字幕和素材引用 |
| PlanRevision | 规划版本、父版本、修改范围、用户确认与预算绑定 |
| Asset | 项目归属、文件 ID、类型、哈希、来源、生成参数、确认状态 |
| Run 和 Step | 固定输入版本、依赖、执行尝试、供应商请求 ID、状态、费用与结果 |
| Delivery | 构建 ID、修订、MP4、剪映工程、素材清单、哈希和兼容说明 |

规划文档与 D 执行工程分开保存，通过编译/映射层把已确认方案转成 D Project。现有画布主要展示执行任务与图层，不能直接当成人物和分镜规划模型。二者通过稳定 ID 关联，避免每次对话重新生成整份工程。

用户改人物或镜头时，后端按依赖标记受影响内容；未受影响的素材按输入和配置哈希复用。旧版预览与工程仍可下载，不能让旧结果静默代表新方案。复用规则须考虑模型配置、提示词、参考素材、裁切及时间参数，不能仅比较文字。

**本地运行架构**

默认沿用 React/Vite 前端和 Python/FastAPI 视频核心。增加独立 Agent Bridge，通过服务端 Codex SDK 对接固定版本的 Codex 运行时；使用可替换 `AgentRunner` 接口，避免页面绑定底层协议。网页连接自有 API 和事件流，不直连 Codex 内部端口。

建议本地控制层使用容器化 PostgreSQL，保存项目归属、会话映射、规划、运行状态、事件、预算和用量。为快速复用，D 核心 SQLite 暂作为单项目执行仓库，使用独立数据目录；它不作为未来 SaaS 钱包和多租户主库。后续可以替换 D Store，或将其保留在独立任务沙箱内，必须显式选定方案并验证迁移。

本轮采用独立调度进程和 Worker，控制层数据库保存任务、租约及投递记录。API 只接收命令、查询和推送事件，不承担视频长任务。远程模型提交、轮询和下载可以分阶段恢复。v0.1 不必增加 Redis，但要保留队列接口；扩展后接外部消息代理仍使用同一套业务任务 ID 和幂等语义。

文件服务采用本地存储适配器，浏览器只见文件 ID 和下载 URL；工作目录由服务端分配。对象存储适配器可在上线阶段接入。API、Bridge、调度器与媒体 Worker 分进程运行。Windows 本机可先使用原生 Python、Node 和 FFmpeg，PostgreSQL 通过容器运行；Linux 容器启动验收列为上线前的单独步骤。

**Codex 接入合同**

每个项目绑定一个持久化 Codex 会话；同一会话的写入按顺序处理。使用独立配置和项目工作目录，插件及服务端配置由平台管理。浏览器发送选中节点、项目与当前修订上下文，后端验证归属后再传给 Agent。

适配器最少提供 `startSession`、`sendMessage`、`resumeSession`、`interruptTurn` 和事件订阅。归一化事件包括消息增量、工具开始与完成、需要用户输入、需要执行授权、规划更新、任务进度、预览就绪、交付就绪、失败及回合结束。事件持久化并有单调序号；终止、重连和重复消息需要有明确语义。

Codex 无法恢复某个旧会话时，保留旧记录，显式新建恢复会话并提供已保存的项目状态；不静默伪造原会话延续。平台只记录可见输出、工具结果和结构化状态，不依赖或宣称提供隐藏推理。

工具分为读取项目、编辑规划、提交制作、查询进度、预览审片和导出。既有 MCP 工具由受控门面调用；项目归属和预算由后端注入并验证。Agent 不能自增余额、提高用户已授权预算或任意指定服务器路径。前端不提供任意插件安装和通用服务器终端。

Codex 内部协议成熟度需在实现时按固定版本复核。官方目前将 App Server 命令及 WebSocket 传输标为实验性、不支持生产工作负载；本地适配验证通过不等于公网生产支持。后续可更换 AgentRunner，而不迁移项目、交付和资金事实。

**预算和执行行为**

本地版展示预计用量、已知实际用量和剩余任务预算，不上线充值，也不伪装成已对账钱包。文本规划调用同样记录费用；供应商费用尚不明确时显示待对账，不显示零成本。

用户可一次授权某个方案的执行范围和预算，在此范围内自动推进。超预算、额外生成、重新付费生成或新增局部烘焙选择时，显示具体差异并请求新的授权。常规已授权步骤不重复打断。

预算检查由后端执行，Agent 无权绕过。初期把主模型和媒体模型统一放到可计量的服务端调用边界；真实供应商凭据不进入浏览器或 Agent 可读工作区。先验证 Codex 与该调用边界的协议兼容，再开展真实付费主链路。

任务状态包含 queued、running、waiting_user、waiting_budget、reconciling、succeeded、failed、cancelled。暂停新增工作不阻断既有请求状态查询、结果下载与对账。超时和崩溃后可能已经提交的远程请求保留请求标识，先查询确认，禁止无条件重发。

本地服务仅监听 loopback，验证 Host/Origin，并保护写接口，避免外部网页驱动本地工具。为未来登录保留可信 owner 上下文；任何从浏览器来的 owner、路径、回调地址和费用数值都不能直接成为授权依据。

**预览片和剪映工程合同**

一次交付绑定固定构建、规划版本和已解析素材。预览与工程必须来自同一组素材、时长、字幕、音轨和布局，不在导出时重新请求模型，也不使用后续已修改的当前工程冒充旧版交付。

复用已有 `delivery → choose_export → export_draft` 流程，补充自包含 ZIP 下载和本地安装辅助。ZIP 包含草稿、素材、所需交付说明及哈希清单。剪映路径重定位由安装步骤完成，不能假设草稿格式支持任意相对路径；在另一目录解压安装后实测。

目标是可编辑多轨工程：视频、图片、字幕和音轨按支持范围保留。复杂效果需要局部烘焙时列出对象和影响，由用户确认；不能整片压平后称为多轨可编辑。明确不支持的效果继续拒绝，不能伪造成功。

本地安装只写入新的、用户选择的目录，不覆盖既有工程；云端上线后交付下载包或由本地辅助程序导入，不允许服务器写用户本机任意路径。首轮以用户当前剪映版本实测，记录版本并作为 v0.1 支持范围。

**第一轮用户验收**

建议样例为 15～30 秒、单人物、3～5 镜头，比例由用户选择，使用已授权参考素材并包含配音或音乐、字幕。时长与镜头数是测试建议，不是产品硬限制。

| 操作 | 应观察到的结果 |
|---|---|
| 首页发送需求和参考图 | 自动进入专属项目，首条消息和附件不丢失 |
| 与 Codex 澄清并修改一处规划 | 右侧人物和分镜随保存结果更新 |
| 授权范围后执行制作 | 可见真实任务进度；成功、失败、等待状态准确 |
| 播放预览 | 画面、字幕、时长、声音符合确认方案 |
| 导出预览及剪映工程 | 对应同一制作版本，产物完整可下载 |
| 剪映打开后改一段字幕或音量并保存重开 | 素材路径正确，实际可编辑，保存不损坏 |

首轮检查从空项目到实际交付，不用固定演示视频替代模型生成和制作结果。

**第二轮用户验收**

| 操作 | 应观察到的结果 |
|---|---|
| 关闭页面并重启本地服务，重新进入首轮项目 | 会话、画布和交付记录可恢复，无重复执行 |
| 指定某个镜头修改人物服装或画面，再改字幕或时长 | 新修订生成；受影响步骤重做，其他结果可验证地复用 |
| 执行期间刷新页面，随后停止并继续 | 不产生重复付费请求；已提交远程任务状态可以解释与恢复 |
| 连点一次提交或导出按钮 | 同一逻辑操作产生一份任务或交付 |
| 再次导出并用剪映打开编辑保存重开 | 新版内容正确，旧版仍可追溯 |
| 新建另一个项目并往返切换 | 会话、素材、规划和结果不会混入另一个项目 |

重启后的远程提交不确定情况通过故障注入单独验证；真实供应商取消能力须独立记录。用户两轮测试覆盖体验，自动化针对幂等、归属、版本绑定和崩溃恢复覆盖数据正确性，不用模拟协议通过替代真实供应商或剪映验收。

**从本地版本到上线**

本地两轮通过后可发布给受控用户试运行，但公开多用户运行前需补登录、可信租户上下文、跨租户访问测试、Agent 与 Worker 执行隔离、私有对象存储、Linux 部署、备份恢复和容量测试。公开收费前再补支付验签、钱包账本、原子冻结结算、退款及供应商对账。

从第一版保留 owner、文件 ID、AgentRunner、事件序号、不可变修订、幂等命令、任务租约和费用事实，使这些上线工作可以逐项接入。即便 UI 不变，本地单用户进程隔离也不能直接视为多租户服务器安全边界。

正式上线前还需按现有 D5-20 继续核对实际分发依赖和许可材料；本地功能验收不替代既有发布事项。

**实现前需确定的配置**

模型接入优先采用用户明确指定的 API 配置，密钥存放在本机服务端秘密配置中。首次真实测试前需确定规划模型、首批媒体模型、允许的测试预算以及剪映版本与草稿位置。上述配置不阻塞页面、契约、恢复机制和本地非付费渲染的开发。
