# 工作流布局与状态同步

2026-10-19，第二次画布修正。第一版把业务对象统一连线，导致同列回绕、输入输出共用端点以及历史版本挤占主线；该版不再作为布局验收依据。

## 主图的语义

- 当前修订每个镜头占一行：镜头输入 → 实际生成任务（仅当构建文档存在该任务）→ 镜头素材。已有素材直接进入素材节点，复用不伪造生成任务。
- 镜头素材经单一汇合线进入本构建的 `$render` 节点，再连到该构建最新的一份 MP4/剪映工程配套交付。等待制作的项目显示明确标注的占位状态。
- 需求、人物和参考文件放公共输入区。辅助引用仅在选择人物/镜头时以虚线出现，不与真实执行依赖混为同类。
- 旧构建、同构建的旧交付包装进入历史侧栏，不占主线；按 `task_id` 保留各自产物归属。新修订未制作时不会冒用旧构建的输出。

## 布局与交互

`web/workflowGraph.ts` 是纯确定性布局函数。固定列、镜头行和列间走线通道，让主线只向右前进；素材通过平滑贝塞尔曲线汇入同一条短主干，使用水平切线衔接。节点使用独立输入/输出端口；同行端口直接连接，辅助引用使用圆滑转弯。曲线控制点限制在列间通道，测试检查控制路径不穿过卡片内部。

允许整行垂直拖动，松开后吸附到空闲行；合成与交付成对移动。这个约束用于保留依赖方向和无障碍走线，不支持任意节点的自由横向拖动。现有行位置固定，新镜头使用空闲位置；“整理布局”清除手动位置。布局、视口按项目保存在浏览器 `videocopyer.workflow.v2.*`，旧版分组位置不混用。150ms 合并视口写入，页面离开时补写。

## 同步开销

结构签名只包括镜头 ID/顺序、真实生成节点 ID、当前构建 ID 和音轨依赖。状态、结果文件就绪、提示词/标题、交付包装变化不触发布局。布局结果与连线路径被缓存，平移/缩放只改变世界坐标变换；历史展开不会重新排列主图。卡片按数据签名 memo，保留未变化的节点与视频 DOM。无需测量卡片 DOM 尺寸；只有画布容器使用 ResizeObserver 处理初次显示。

沿用已有 SSE 与 4 秒轮询回退，不增加同步定时器、后台任务、模型调用或 Agent 等待步骤。所有布局都在浏览器执行，不在制作 Worker、Codex 会话或模型上下文里执行/传递坐标。

## 验证与测量

- `npm run test:workflow`：真实生成/复用分支、行对齐、单汇合线、走线通道、拖动后卡片避让、插入新镜头保留原位置、状态变化不使结构签名失效。附带纯 JS 布局 100 次样本的 p50/p95，见 `evidence/workflow-graph-tests.json`。
- `npm run test:workflow-browser`：真实双镜头文件可播放、一个当前交付、历史包装可展开；选择引用、平移/缩放不重新计算布局；行位置刷新恢复；编辑/预算弹窗、空项目、390px 窄屏；未制作的新修订不显示旧产物。见 `evidence/workflow-browser.json`。
- 浏览器规模测试使用 10/50/100 镜头，即 32/152/302 个任务/资源节点的合成快照。测量一次初始布局及一次状态响应到 DOM 变化的时间；同时核对布局计数和连线路径没有变化。所有写请求被阻止，预算预留前后相同。

浏览器数据是本机单次开发者样本，不是 p95 或 SLA；响应到 DOM 耗时不含供应商执行、网络、等待下一次轮询、GPU 最终显示和视频解码。规模快照不播放真实媒体。不会用该数据宣称端到端实时延迟为几毫秒。

当前仍是本地应用对 D 数据的工作流投影，没有宣称完整迁移原 D 服务端画布协议、归档、审片反馈或剪映编辑能力。
